# Tasks + History

Перед запуском backend примените миграции из папки `backend/`:

```sh
npm run migration:run
npm run start:dev
```

Все маршруты требуют `Authorization: Bearer <accessToken>`. Swagger доступен в `/docs`.

## Личные задачи

| Метод  | Маршрут                     | Назначение                                            |
| ------ | --------------------------- | ----------------------------------------------------- |
| POST   | `/tasks`                    | Создать задачу: `title`, необязательное `description` |
| GET    | `/tasks?status=in_progress` | Свои задачи, необязательный фильтр по статусу         |
| GET    | `/tasks/:id`                | Получить свою задачу                                  |
| PATCH  | `/tasks/:id`                | Изменить `title`, `description` или `status`          |
| DELETE | `/tasks/:id`                | Удалить свою задачу                                   |

Статусы: `todo`, `in_progress`, `completed`. Одновременно у пользователя может быть только одна задача `in_progress`. Ограничение действует и при параллельных запросах; конфликт возвращает `409 ACTIVE_TASK_EXISTS`.

Название обрезается по краям и содержит от 1 до 120 символов, описание — до 5000. Для очистки описания передайте `null` или пустую строку. `completedAt` устанавливается при переходе в `completed` и очищается при возвращении к другим статусам. Повторная установка `completed` сохраняет первоначальную дату завершения.

Чтобы выбрать задачу для следующего Focus:

```http
PATCH /tasks/<taskId>
Content-Type: application/json

{ "status": "in_progress" }
```

Перед выбором другой задачи переведите прежнюю активную задачу в `todo` или `completed`. Сама задача может занимать несколько Focus: окончание таймера не завершает задачу автоматически.

## Привязка к Pomodoro

Владелец запускает таймер существующим Socket.IO событием `pomodoro:start` с `{ roomId }`. Сервер создаёт постоянный `pomodoroSessionId` и фиксирует участников комнаты и активную задачу каждого из них. Задача необязательна. Клиент получает ID в `room:snapshot` и `pomodoro:state`.

Название задачи сохраняется снимком при старте. Изменение задачи во время Focus применяется к следующему запуску. Удаление задачи очищает `taskId` в истории, сохраняя снимок `taskTitle`.

Участники фиксируются на старте Focus. Вступивший позже пользователь участвует в истории со следующего запуска. Это позволяет однозначно определить выбранные задачи и время участия.

## Автоматическая история

- При окончании Focus сервер сохраняет `completed` и запускает Break на 5 минут.
- При `pomodoro:cancel` во время Focus сохраняется `cancelled`. Отмена Break сохраняет ранее записанный результат Focus.
- HTTP `POST /rooms/leave` сразу завершает личное участие со статусом `cancelled`. Если срок Focus уже истёк, результат будет `completed`. Повторное вступление в тот же Focus не создаёт вторую запись.
- Когда последний участник покидает комнату, незавершённый Focus закрывается, включая таймер на паузе.
- Разрыв Socket.IO соединения и событие `room:leave` означают отключение от канала, а не выход из участников комнаты. Членство меняется через HTTP `/rooms/leave`.

`focusedSeconds` считает время работающего Focus, пока пользователь числится участником комнаты. Паузы и время после выхода не учитываются; неполные секунды отбрасываются в конце. Это время участия в таймере, а не измерение внимания пользователя.

Запись истории и изменение таймера выполняются в одной транзакции. Пара `(userId, pomodoroSessionId)` уникальна. Параллельные обращения, повторные команды и восстановление после перезапуска сохраняют один результат на участника. Незавершённые запуски и накопленное время хранятся в PostgreSQL.

История начинается с запусков Focus, созданных после новой миграции. Уже работающие старые таймеры продолжают свою фазу; история для них задним числом не восстанавливается.

## Чтение истории

| Метод | Маршрут          | Назначение                                                       |
| ----- | ---------------- | ---------------------------------------------------------------- |
| GET   | `/history`       | Свои записи: `{ items, total }`                                  |
| GET   | `/history/rooms` | Комнаты из собственной истории: `{ id, name }[]`                 |
| GET   | `/history/:id`   | Одна своя запись                                                 |
| GET   | `/history/stats` | Количество сессий, завершений и отмен, суммарное и среднее время |

Список поддерживает `status=completed|cancelled`, `roomId` (UUID), `from`, `to`, `limit` (1–100, по умолчанию 50), `offset` (от 0). Статистика поддерживает `status`, `roomId`, `from`, `to`. Все фильтры пересекаются с текущим пользователем; чужие комнаты не раскрывают историю. Период сравнивается с `startedAt`: начало включительно, конец не включительно. Даты передаются в ISO 8601; `from` должен быть раньше `to`.

Запись содержит `taskId`, `taskTitle`, `roomId`, `roomName`, `pomodoroSessionId`, `status`, `plannedDurationSeconds`, `focusedSeconds`, `startedAt`, `endedAt`, `createdAt`. Отсутствующая или удалённая задача имеет `taskId: null`. При удалении комнаты история сохраняется с `roomId: null`, а `roomName` остаётся снимком названия на старте Focus. `GET /history/rooms` возвращает уникальные ненулевые `roomId` только из личной истории; название берётся из последней сессии этой комнаты. Удалённые комнаты остаются видны в общей истории без отдельного фильтра.

Результаты формирует сервер. HTTP создания, изменения и удаления истории отсутствуют. XP, Coins, персонажи, награды и достижения относятся к следующим этапам.

## Проверки

```sh
npm run build
npm test -- --runInBand
npm run test:e2e
```

Интеграционные тесты используют отдельную БД с именем, оканчивающимся на `_test`, и пересоздают её схему. В `.env.test` должны быть параметры этой БД. Набор проверяет миграцию и откат, изоляцию задач и истории, гонку активных задач, снимки названий, паузы, восстановление, выход участников, повторную финализацию и откат общей транзакции при ошибке.

## Названия и фильтр комнат

Миграция `HistoryRoomNames1794960000000` добавляет nullable `room_name` в `pomodoro_runs` и `focus_history` и индекс для фильтрации. Существующим записям подставляются названия сохранившихся комнат. Для уже удалённых комнат название восстановить нельзя; API возвращает `null`. Новые запуски сохраняют название внутри транзакции таймера, включая отмену и выход участника.

Frontend передаёт границы диапазона в ISO 8601. UI включает последний выбранный день через передачу полуночи следующего дня в эксклюзивный параметр `to`.
