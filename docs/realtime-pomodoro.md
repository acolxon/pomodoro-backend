# Realtime и общий Pomodoro

Socket.IO подключается к тому же origin, что и HTTP API. Передайте access JWT в `auth.token`:

```ts
const socket = io(API_URL, { auth: { token: accessToken } });
```

## События клиента

Все события ниже принимают `{ roomId: string }`.

- `room:join` — проверить членство и подписаться на комнату. Сервер отправляет `room:snapshot` с комнатой, участниками, состоянием Pomodoro и `serverTime`.
- `room:leave` — отписать только этот сокет от канала комнаты; это не HTTP-выход из состава. `POST /rooms/leave` меняет членство и отписывает от комнаты все вкладки пользователя.
- `pomodoro:start` — владелец запускает 25-минутный Focus из состояния `idle`.
- `pomodoro:pause` — владелец ставит активную фазу на паузу.
- `pomodoro:resume` — владелец продолжает паузу.
- `pomodoro:cancel` — владелец сбрасывает таймер в `idle`.
- `pomodoro:ready` — `{ roomId, ready: boolean }`: участник отмечает или снимает готовность до запуска. Для готовности нужна личная активная задача.
- `pomodoro:leave` — участник выходит из текущего Focus, оставаясь в комнате; общий таймер не останавливается. Повторный вход в тот же Focus невозможен.

Управление доступно только владельцу комнаты. Socket должен предварительно выполнить `room:join`.
Готовность и личный выход доступны каждому участнику; для старта нужны готовность и активная задача у всех активных участников комнаты. После запуска готовность сбрасывается. Поздно вошедший остаётся наблюдателем. Событие `room:updated` обновляет статусы при смене фазы, выходе и сбросе готовности из-за завершения или удаления задачи.

## События сервера

- `realtime:ready` — JWT принят.
- `realtime:error` — ошибка подключения/аутентификации.
- `room:snapshot` — полный снимок комнаты при входе.
- `pomodoro:state` — новое состояние таймера, отправляется всем подключённым участникам.
- `room:updated` — `{ roomId }`, состав или владелец изменились. Клиент перечитывает `/rooms/me` и `/rooms/:id/members`. При создании/вступлении уведомление получают также другие подключённые вкладки этого пользователя, ещё не подписанные на комнату.
- `room:removed` — `{ roomId, reason: 'left' | 'closed' }`. Все соответствующие сокеты уже отписаны от комнаты; клиент очищает старое состояние и перечитывает текущее членство.
- `exception` — `{ code, message }`, ошибка команды с кодом REST (`NOT_IN_ROOM`, `ROOM_CLOSED`, `FORBIDDEN`, `VALIDATION_ERROR` и др.). Неизвестные ошибки не раскрывают внутренние данные сервера.

Состояние содержит `status`, `phase`, `durationSeconds`, `startedAt`, `endsAt`, `pausedAt`, `remainingSeconds`, `serverTime` и `pomodoroSessionId`.

`pomodoroSessionId` — постоянный UUID конкретного запуска Focus. Он сохраняется при паузе, продолжении и переходе к Break; в `idle` равен `null`. История всех участников одного запуска ссылается на этот UUID. Сохранение результатов выполняется сервером автоматически; подробности и HTTP API описаны в [Tasks + History](tasks-history.md).

`GET /history/sessions/:id/results` возвращает итоги завершённого запуска только его участникам: результат, причину, задачу, время и начисленную награду каждого. До окончания всего запуска запрос возвращает конфликт. Повторные начисления защищены журналом; вышедший досрочно получает отменённый личный результат без XP и монет. Новая миграция `SessionReadiness1795132800000` добавляет готовность, причины завершения и уникальный индекс одного незавершённого участия на пользователя; при наличии конфликтующих старых записей миграция остановится, не удаляя данные.

Клиент не должен отправлять секундные тики. Для обратного отсчёта используйте `endsAt - serverTime`, корректируя разницу часов по `serverTime`. После reconnect снова отправьте `room:join` и используйте новый snapshot.

Focus длится 25 минут, затем автоматически начинается Break на 5 минут. После Break состояние возвращается в `idle`. `cancel` также возвращает `idle`. Состояние хранится в PostgreSQL и восстанавливается при старте backend.

## Ограничение паузы

`POMODORO_MAX_PAUSE_SECONDS` — целое число от 1 до 86400, по умолчанию **900** (15 минут). Добавьте его в окружение backend при необходимости изменить предел:

```dotenv
POMODORO_MAX_PAUSE_SECONDS=900
```

Дедлайн вычисляется из сохранённого `pausedAt`, дополнительная миграция не нужна. По истечении лимита Focus сохраняется как `cancelled`, время паузы не засчитывается. В `endedAt` записывается дедлайн паузы, даже если сервер обработал его позднее. Для Break отмена паузы сбрасывает таймер в `idle`, сохраняя уже полученный результат Focus. После перезапуска восстанавливаются и работающие, и приостановленные таймеры. Закрытие комнаты снимает локальное расписание; закрытая комната не может запустить таймер снова.

## Согласованность и Origin

Изменения состава публикуются после commit. Подписка сокета и финальное чтение/отправка snapshot сериализуются с HTTP-выходом по блокировке комнаты; снимок комнаты, участников и таймера читается в одной транзакции без вложенных транзакций. На клиенте поздние acknowledgements дополнительно отсекаются при смене комнаты, соединения или получении более свежего события.

Socket.IO использует тот же список `CORS_ORIGINS`, что HTTP. Список разделяется запятыми. Кроме CORS-заголовков адаптер проверяет `Origin` при handshake, включая WebSocket transport. Неизвестный Origin отклоняется; отсутствие Origin допускается для CLI и тестовых клиентов, JWT всё равно обязателен. При локальной работе через `http://127.0.0.1:5173` добавьте этот точный origin в список наряду с `http://localhost:5173`, если используете оба адреса.

Приложение по-прежнему использует один экземпляр backend и стандартный Socket.IO adapter. Ошибка доставки уведомления журналируется и не превращает уже закоммиченную HTTP-операцию в ошибку; актуальное состояние восстанавливается при reconnect/возврате на вкладку/ручном обновлении. Долговечная очередь событий и координация нескольких экземпляров backend в этой итерации не добавлялись.
